# Code map

How Absorb Plus is put together and where to look. The layout under `lib/` is upstream's ([pounat/absorb](https://github.com/pounat/absorb)). It stays as is so upstream merges stay clean; see "Fork rules" at the end.

## Start-up and navigation

| Where | What |
|---|---|
| `lib/main.dart` | `main()` sets up certificates, image cache limits and read-along, then `MultiProvider` (`AuthProvider`, `LibraryProvider`). `_initServices` starts audio first, then optional services in the background through `StartupTaskCoordinator` (fork). |
| `lib/screens/app_shell.dart` | The main window after sign-in. Its tabs are 0 Home, 1 Library, 2 Absorbing (now playing and queue), 3 Stats and 4 Settings. Pages are built lazily and kept alive. It also hosts the expanded player, keyboard shortcuts, the nav hold menu and update checks. There is no desktop sidebar: desktop uses the same bottom navigation. |
| `lib/screens/login_screen.dart`, `lib/models/auth_session.dart` | Sign-in, including OIDC and multiple accounts. |

## State (providers)

- **`AuthProvider`** (`lib/providers/auth_provider.dart`) holds the server URL, tokens, the user JSON and permissions (`isAdmin`, `canUpload` from the fork), multiple accounts and the signed-out state. It owns the `ApiService`.
- **`LibraryProvider`** (`lib/providers/library_provider.dart`) is one class assembled from three `part` mixins:
  - `_lp_state.dart`: the fields.
  - `_lp_core.dart`: loading libraries and shelves, progress, offline mode, downloaded shelves.
  - `_lp_absorbing.dart`: the Absorbing queue.

  Most widgets `context.watch` the whole provider (about 50 places), so any notification rebuilds them; only a few use `context.select`. Cards use `LibraryItemSnapshot` (fork) to avoid rebuilding on every notification.

## Screens and widgets

- `lib/screens/` holds full pages. `settings_screen.dart` (about 6,000 lines) contains every settings section, including Settings → Advanced, which hosts ReadMeABook and transcription. The `admin_*` files are server admin pages.
- `lib/widgets/` holds sheets, cards and controls. Cards that rebuild with playback are `absorbing_card.dart`, `card_progress_bar.dart`, `card_edge_progress_bar.dart` and `card_buttons.dart`.

## Strings

`lib/l10n/app_en.arb` is the source. Other languages have their own `.arb` files. The `app_localizations*.dart` files are generated by `flutter gen-l10n`; untranslated keys fall back to English. The fork dropped `untranslated-messages-file` from `l10n.yaml`: writing that report made every `pub get` about 18 s slower locally (about 50 s in CI). To see the untranslated keys, add the line back temporarily and run `flutter gen-l10n`.

## Fork rules (why the layout isn't reorganized)

The fork keeps merging upstream, which ships changes almost daily. Moving or reformatting upstream files would turn each merge into hundreds of conflicts. So:

1. **New fork features go in new files.** Upstream files get only small hooks: an import, a callback, a tile.
2. **Never reformat upstream files.** Run `python tool/align_with_upstream.py FILE...` to see, and `--apply` to undo, formatting churn. It only rewrites a file when the result is token-identical.
3. **To find the fork's footprint:** `git diff --stat origin/main -- lib ':!lib/l10n'`.
4. **Imports the fork adds to an upstream file go in one marked block** after upstream's imports (`python tool/group_fork_imports.py --all`).
5. **Fork startup work goes in `lib/fork/fork_startup.dart`**, which upstream's `main()` calls twice. `lib/fork/` is where such plug-in points live.

## Fork conventions (new and touched fork code)

- **Platform checks:** use `ForkPlatform` (`lib/utils/fork_platform.dart`: `isWindows`, `isDesktop`, `supportsCast`…), not `Platform.is…` or `defaultTargetPlatform` by hand. Tests can set `ForkPlatform.debugIsWebOverride`. Native-only files (FFI, `dart:io` conditional imports) may ask the OS directly.
- **Upstream's web/desktop port:** upstream gates its web code on `AppPlatform.lacksPhonePlugins` (upstream: `isWeb || isDesktop`, sending desktop down the web paths) and its sidebar workspace on `isDesktopWorkspace`. The fork's one-line hook in `lib/utils/app_platform.dart` makes `lacksPhonePlugins` web-only, so Windows and Linux run the phone paths (downloads, EQ, local server, OIDC, updater) and keep the fork's UI; a phone-only plugin call reached on desktop needs a `ForkPlatform` capability check. On web, `ForkPlatform.webUsesOriginServer` decides whether the sign-in screen takes the server from the page origin (upstream) or shows the server field (GitHub Pages, localhost). Tests: `test/platform_hooks_test.dart`.
- **Errors:** no empty `catch`. Either a comment says why the error doesn't matter, or the block calls `swallow(tag, e)` from `lib/utils/fork_errors.dart`. Don't drop a `Future` silently: `await` it, wrap it in `unawaited(...)` when its own code handles failure, or use `fireAndLog(future, tag)`. `tool/fork_lints.py` enforces both.
- **Logging:** `debugPrint('[Tag] message')`. `LogService` masks tokens and server addresses, but never put a token, password or full signed URL in a message anyway.
- **Services:** one shared instance as `static final instance = Foo._();`, plus a `@visibleForTesting` constructor or setter when tests need a fake. Older fork services that are reached another way stay as they are until touched.
- **Settings keys:** new keys are `fork_snake_case`, declared once as a constant in the owning service. `python tool/pref_keys.py` shows where any key is used. Never rename an existing key: users would lose the saved value.
- **Formatting helpers:** `lib/utils/fork_format.dart` (`formatBytesFine`) and upstream's `lib/utils/file_size.dart` (`formatFileSize`). Check them before writing another.
- **Tests:** shared fakes are in `test/support/fakes.dart` (`FakeAuth`, `mockApi`, `fakePathProvider`, `fakePackageInfo`, `fakeWindowsShell`). Every behavior change gets a test that fails without it.
- **Finding your way:** `python tool/code_map.py FILE` before reading a large file; `--find NAME` to locate a declaration.
